# Digital identity / design direction

Audience: potential collaborators and hiring teams evaluating Ali's full stack engineering practice. Primary task: understand the person, verify relevant work/experience and contact him or download his résumé.

Use a Swiss editorial grid as a digital archive: oversized two-line name, small monospaced index annotations, an original portrait framed by a restrained technical coordinate system, thin rules, asymmetric work studies and a legible experience/learning archive. The instrumentation expresses a structured identity, not fabricated system telemetry. Avoid gaming chrome, terminal wallpaper, random neon, repeated cards, decorative metrics and unsupported availability indicators.

Default: Ozone / Dark. Retain exact defining colors in the centralized collection data. Derive independent, deliberate light/dark semantic roles; ensure accent fills have contrasting paired text instead of assuming the raw accent can be used for small text on every surface. Keep controls, portraits, vector schematics, navigation and the laboratory on the same token system.

Type: self-hosted Space Grotesk (variable 400–700) for display and reading; IBM Plex Mono for compact annotations. Use a large scale and intentional letter spacing in the name; ordinary reading copy stays at a comfortable size/measure. A single display/body family keeps downloads small.

Composition: a bounded 12-column desktop canvas, vertical archive rail, strong shared edges, variable section proportions. Selected work uses a large lead contribution and two unequal study regions. Experience uses a wide editorial row, not a collection of generic cards. Narrow screens move to a purposeful single/two-column composition; long email addresses can wrap; navigation becomes a disclosure; the laboratory uses a full-height mobile sheet with reachable actions.

Interaction: native dialog for the color laboratory with keyboard containment, Escape and focus return; independent collection and appearance; previews are ephemeral; only Lock writes the pair to a first-party preference cookie; Return restores the last committed pair; Reset clears the preference and returns to Ozone/Dark. Server rendering validates that cookie and supplies the same initial pair to the document and layout, so the saved colors are present before hydration. Per-layout context owns reactive state, avoiding shared mutable server state.

Motion: brief hover translation, a restrained initial typography entrance, explicit color transitions disabled for reduced motion. No scroll hijacking, continuously running visual noise, or content hidden pending animation.

Verification: type check, production build, MCP autofixer, all 20 rendered themes with contrast checks, representative full-page/hero/mobile screenshots, temporary/locked/reload/reset/return state tests, keyboard dialog and navigation, portrait/resumé/anchor checks, responsive overflow, reduced motion, production request/console observations. Record unverified external links and physical-device/screen-reader limits honestly.
